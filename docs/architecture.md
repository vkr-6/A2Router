# Architecture and lifecycle

Python 3 manages typed device/route/virtual definitions, JSON persistence, CLI and PySide6 widgets. A single Qt background executor serializes backend operations and disk IO; snapshots cross into the GUI by Qt signals. The server or native C++ engine carries PCM independently of widget repainting. A per-user advisory lock prevents competing CLI/GUI writers. Diagnostics and device enumeration are read-only. Mock sessions are labeled simulated and stored separately.

Linux owns modules; Windows owns native source sessions and uses the externally installed/shared VB-CABLE driver. Route IDs and virtual-definition UUIDs belong to the application; OS resource IDs are observations only. Linux close leaves modules running, and startup adopts tagged resources matching restored definitions. Unknown owned modules are reported as stale, not automatically deleted. Explicit `cleanup` handles orphaned owned resources, unloading loopbacks before sinks. Virtual device removal refuses while dependent desired routes exist. Stop/disable/remove, listing routes and exporting profiles never start missing routes simply to manage them.

Creation verifies server-side endpoints/attachments. When verification fails, creation rolls back only modules that match this owner's tags and definition ID; cleanup errors are returned. A failed route remains a desired route with an error, rather than being mislabeled connected. Separate destination routes have independent success/error states: one failed destination does not conceal the successful destinations. All enabled routes revalidate safety and matching layouts when refreshed; disabled desired routes participate in cycle detection so enabling later cannot bypass safety checks.

Version 1 configuration persists virtual definitions, route IDs, stable endpoint names, enabled state, explicit monitoring confirmation and a validated `channel_map` list and an optional nonnegative `delay_ms` request (default zero for older version-1 profiles). Windows mappings contain zero-based source/destination indices and finite linear gains; unsupported backends reject nonempty maps. Optional `endpoint_aliases` persist A2Router display names; old profiles without aliases remain valid. Unknown fields, unsupported versions, wrong booleans/types, duplicates and invalid UUIDs are errors. JSON profiles are named files chosen through dialogs; load merges and rejects ID conflicts. Writes validate first, flush/fsync a temporary sibling, then atomically replace the target. A failed parse/write does not replace the valid file. Missing/incompatible endpoints and failed virtual definitions remain desired definitions for later recovery. Only version 1 exists, so there is no invented migration from an undocumented previous schema.

Server resources and JSON cannot participate in one atomic transaction. A process or disk failure between module creation and session persistence can leave tagged orphan resources; diagnostics and explicit cleanup are provided. Resource ownership is cooperative tagging, not a security boundary against another client with the same audio-server permissions. Device names are stable under ordinary reconnects but may change under different server profiles; routes are never redirected based on array position or display name.

Polling is a safety fallback alongside Linux subscriptions. Continuous recovery requires the controller to run; server modules remain after Linux controller exit but are not persisted by the audio server across its restart. Windows engine teardown runs on the worker before GUI exit. The UI hides/minimizes on window close, has explicit Exit and Stop actions, and displays backend errors. Control teardown on exit is idempotent.

Standard routing preserves server mixing and the existing WASAPI conversion path. Optional Windows channel matrices add explicit remapping, duplication and per-destination summing in double precision, with float32 output and peak clipping. Linux native mixing and clock adaptation are delegated to PipeWire. The Windows clock controller and lock-free queues were reused. Tone tests verify transport/channel order at low levels through a virtual graph; they do not establish a bit-perfect path or sample-accurate alignment of real hardware. The optional channel editor is only enabled when the backend reports the native matrix ABI.

Windows driver operations run only from explicit Virtual devices actions, using the original VB-CABLE package. The portable app requests an elevated helper and waits on the worker, never on the GUI thread. The helper validates the vendor installer signature and verifies PnP status independently of vendor return codes. Ready active endpoints are used immediately; pending restarts and unavailable endpoints are reported. Uninstallation requires explicit confirmation and removal of dependent routes. Opening the app or restoring definitions cannot install a driver. Name aliases are local; Windows Sound manages actual endpoint names, speaker layouts and formats. No certificate/boot policy is changed.

UI refresh applies stable-ID updates to existing items and leaves draft delay edits alone. Foreground actions arriving during a background poll are queued. Supported live delays update the native output target and Python session cache together, preventing the next poll from restarting that source.
