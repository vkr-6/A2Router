# Architecture and lifecycle

Python 3 manages typed device/route/virtual definitions, JSON persistence, CLI and PySide6 widgets. A single Qt background executor serializes backend operations and disk IO; snapshots cross into the GUI by Qt signals. The server or native C++ engine carries PCM independently of widget repainting. A per-user advisory lock prevents competing CLI/GUI writers. Diagnostics and device enumeration are read-only. Mock sessions are labeled simulated and stored separately.

Linux owns modules, Windows owns a native engine. Route IDs and virtual-definition UUIDs belong to the application; OS resource IDs are observations only. Linux close leaves modules running, and startup adopts tagged resources matching restored definitions. Unknown owned modules are reported as stale, not automatically deleted. Explicit `cleanup` handles orphaned owned resources, unloading loopbacks before sinks. Virtual device removal refuses while dependent desired routes exist. Stop/disable/remove, listing routes and exporting profiles never start missing routes simply to manage them.

Creation verifies server-side endpoints/attachments. When verification fails, creation rolls back only modules that match this owner's tags and definition ID; cleanup errors are returned. A failed route remains a desired route with an error, rather than being mislabeled connected. Separate destination routes have independent success/error states: one failed destination does not conceal the successful destinations. All enabled routes revalidate safety and matching layouts when refreshed; disabled desired routes participate in cycle detection so enabling later cannot bypass safety checks.

Version 1 configuration persists virtual definitions, route IDs, stable endpoint names, enabled state, explicit monitoring confirmation and an empty reserved `channel_map` list. Nonempty mappings are rejected until implemented. Unknown fields, unsupported versions, wrong booleans/types, duplicates and invalid UUIDs are errors. JSON profiles are named files chosen through dialogs; load merges and rejects ID conflicts. Writes validate first, flush/fsync a temporary sibling, then atomically replace the target. A failed parse/write does not replace the valid file. Missing/incompatible endpoints and failed virtual definitions remain desired definitions for later recovery. Only version 1 exists, so there is no invented migration from an undocumented previous schema.

Server resources and JSON cannot participate in one atomic transaction. A process or disk failure between module creation and session persistence can leave tagged orphan resources; diagnostics and explicit cleanup are provided. Resource ownership is cooperative tagging, not a security boundary against another client with the same audio-server permissions. Device names are stable under ordinary reconnects but may change under different server profiles; routes are never redirected based on array position or display name.

Polling is a safety fallback alongside Linux subscriptions. Continuous recovery requires the controller to run; server modules remain after Linux controller exit but are not persisted by the audio server across its restart. Windows engine teardown runs on the worker before GUI exit. The UI hides/minimizes on window close, has explicit Exit and Stop actions, and displays backend errors. Control teardown on exit is idempotent.

No custom mixer, resampler or hardware synchronization algorithm was introduced. Linux native mixing and clock adaptation are delegated to PipeWire. The Windows clock controller and lock-free queues were reused. Tone tests verify transport/channel order at low levels through a virtual graph; they do not establish a bit-perfect path or sample-accurate alignment of real hardware. No unsupported tuning sliders or per-channel patchbay is exposed.
